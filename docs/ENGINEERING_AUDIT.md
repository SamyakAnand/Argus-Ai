# ARGUS AI Engineering Audit

**Audit date:** 2026-11-14
**Scope:** Repository source, tests, dependency manifests, database DDL, Docker/Compose, Vercel routing, CI, frontend API calls, and existing architecture/security/evaluation documentation. Read-only audit; no live service or production credentials were exercised.

## Architecture and verified capabilities

- `apps/api/nexus_api/main.py` is a single FastAPI application serving both the lexical `/knowledge` prototype and legacy structured-data analytics routes. `apps/web/src/lib/api.ts` is the browser API client; the web app proxies `/api/*` to the API service.
- Analytics loads tabular data into process-global pandas frames and registries. Implemented operations include file upload/preview/export, profiling, deterministic cleaning, read-only SQL on in-memory frames, statistical/anomaly/clustering/forecasting analysis, reports, fixture evaluation, REST/SQL source previews and ingestion, relationship inference, reconciliation, and source lineage.
- Knowledge accepts UTF-8 TXT/Markdown, stores originals and chunks in a local SQLite database, scopes those rows to a principal derived from verified Clerk `sub` or a configured local-only development token, and returns lexical excerpts with source offsets. Optional model synthesis is configured separately and citation checks are structural; it is not semantic entailment.
- Existing tests cover deterministic analytics, file parsing, knowledge upload/search/answer shapes, local/Clerk principal separation for knowledge, provider error behavior, and synthetic fixture metrics.

## Findings

| Area | Current state and evidence | Risk / missing proof |
|---|---|---|
| Authentication and tenancy | Clerk verification and principal filtering exist in `knowledge.py` only. Analytics routes for datasets, SQL, analyses, reports, sources, reconciliation, and evaluation have no identity dependency. Analytics datasets/runs have no owner field. | Private analytics and connector routes are anonymous and cross-user access is not modeled. Knowledge SQLite is separate from analytics persistence. No PostgreSQL RLS or workspace policy exists. |
| Demo boundary | `demo-sales` is loaded into the same global registries as user uploads; routes do not distinguish anonymous demo access from private resources. | No controlled anonymous read-only demo workspace boundary. |
| Database and persistence | `db.py` defines SQLAlchemy records for datasets, runs, reports, inquiries and uses `create_all`; default is SQLite. `_get_engine()` and `init_db()` silently fall back to SQLite when a configured engine fails. `main.py` keeps frames/metadata/runs in memory, mirrors files and JSON manifests, and swallows persistence exceptions. Knowledge has its own SQLite schema and on-demand DDL. | PostgreSQL is not an authoritative persistence layer; application restart/serverless behavior is not durable. Docker's `database/init.sql` schema is not represented by Alembic and differs from the ORM (`source_filename`/`file_format` vs `filename`/`format`/`storage_path`, UUID vs string IDs, and table relationships). Migration compatibility is unverified. |
| Uploads and documents | Analytics uploads allowlisted structured formats, capped by bytes, parsed synchronously, and written under `DATA_DIR`; knowledge accepts only TXT/Markdown up to 5 MiB and stores source text in SQLite. | No object store, content signature verification, malware policy, parser isolation, PDFs/DOCX, version/delete lifecycle, durable ingestion job, or restart recovery. |
| Connectors | REST connector supports caller-provided URL, headers, auth, pagination and uses `httpx.Client(follow_redirects=True)`; SQL connector creates an engine from a caller-supplied connection URL and accepts SQL/table values. Preview/connect routes are unauthenticated. | SSRF, private/link-local/reserved destination access, redirect pivoting, DNS rebinding, credential leakage, arbitrary SQL source reads, and unbounded response bytes are not controlled. Exception text can leave the process. |
| Retrieval and answer generation | Knowledge retrieval scans principal-filtered SQLite chunks and ranks capped lexical term frequency. `database/init.sql` declares `knowledge_embeddings VECTOR(384)` but no application write/query uses it. `knowledge_eval_v1.json` / fixtures are small synthetic checks. | No PostgreSQL full-text search, embedding generation, pgvector query, RRF, reranker, document-level ACL, source/span integrity check, entailment check, contradiction validation, or representative benchmark. Do not describe this as hybrid RAG. |
| Providers | `llm.py` and `gateway.py` both implement provider selection/calls; analytics currently synthesizes through `llm.py`, while `gateway` is imported but not used for its advertised planning workflow. Provider status is configuration-derived. Gemini credentials are placed in a query parameter in the existing provider implementation; broad exception handling can obscure provider failures. | No single gateway, reliable reachability/inference distinction, bounded unified retry/circuit handling, or comprehensive usage/cost quotas. API key presence is not provider health. |
| Health and observability | `/health` reports static `status: ok`, configured provider/model, and `langgraph_runtime: active`; it does not probe database/worker/provider readiness. Request/trace IDs, structured audit events and operational metrics are not established. | Misleading operational state; no worker exists despite Redis being provisioned. LangGraph dependency/status is unsupported by a tested graph workflow. |
| API and frontend contracts | API is route-heavy in `main.py`; browser client in `apps/web/src/lib/api.ts` calls analytics and connector endpoints without Clerk tokens (Clerk token is only attached to `/knowledge/*`). `/reports/generate` returns text while the generic request helper expects JSON, and report fetch has separate error handling. | Enforcing auth without updating the web request flow would break analytics. No contract/openapi regression suite or client-server auth contract exists. |
| Analytics safety | Analytics computations are deterministic and tests cover several numerical paths. SQL validation uses a deny-list plus SQLite execution on a temporary in-memory frame. | No SQL AST validation, query execution timeout/resource governor, dataset-version provenance, strict tool registry, or cross-tenant authorization. The deny-list is not a complete SQL policy. |
| Dependencies and dead/duplicate code | Python requirements and `pyproject.toml` overlap; Redis and LangGraph are declared but no RQ worker or actual LangGraph flow is wired. `gateway.py` duplicates provider responsibilities. Parquet parsing/tests used pandas but the required Parquet engine was not declared; `pyarrow>=16` is now included in both manifests. The repository ignores `apps/api/uv.lock`. | Dependency purpose/version pinning and vulnerability scans are absent. Remove dependencies only after proving no live usage. |
| CI and tests | `.github/workflows/ci.yml` runs API pytest and web `npm ci`, TypeScript check, and production build. API tests now include a focused database failure module. | No configured PostgreSQL integration service/migration test, explicit full legacy-route auth negatives, connector SSRF regression coverage, ingestion-worker lifecycle, provider retry circuit tests, vulnerability scan, or end-to-end system test. API suite was run after this audit slice: **53 passed** with Python 3.12 via uv; no PostgreSQL integration was exercised. |
| Deployment | Compose starts API, web, PostgreSQL/pgvector, and Redis; API mounts a persistent volume. Vercel routes API and web as services; `main.py` uses `/tmp` for Vercel data. | Compose provisioning does not make PostgreSQL/Redis authoritative; Vercel `/tmp` is ephemeral. No object store, worker service, production migration command, or verified backup/restore path. No deployment was inspected live. |

## Duplicate implementations, dead code, and coverage gaps

- Provider selection, calls, retries, and fallback behavior overlap in `llm.py` and `gateway.py`; only the `llm.py` synthesis path is active in analytics.
- `gateway` and `plan_with_llm` imports in analysis code are not evidence of an active planning pipeline. `langgraph_runtime: active` is not backed by a graph runtime in the route path.
- Redis and pgvector appear in dependencies/infrastructure/DDL only; the API has no worker queue or vector ingestion/search path.
- Analytics global process state, SQLite/SQLAlchemy state, JSON manifest, and file copies duplicate persistence responsibilities.
- Contract tests do not currently establish authentication on legacy private endpoints, PostgreSQL migration alignment, SSRF controls, durable upload recovery, or semantic citation support.

## Audit limitations

This review describes checked-in code/configuration and existing tests. No production runtime, deployment secrets, customer data, live database, provider inference, external connector target, or browser session was exercised. Claims above are bounded to code paths inspected; tests are not claimed as passing until run.

## Initial implementation slice and verification

- Removed silent SQLite fallback from database engine construction and schema initialization. Startup restoration now propagates initialization failure instead of continuing with manifest-backed state.
- Added three regression tests covering engine construction, schema initialization, and startup restoration failure behavior.
- Declared the Parquet runtime engine `pyarrow>=16` in `requirements.txt` and `pyproject.toml`. `apps/api/uv.lock` is ignored by the repository, so no lockfile change is part of this branch.
- Focused command: `uv run --directory apps/api --python 3.12 --with pytest pytest -c pytest.ini tests/test_db.py -q` — **3 passed**.
- Full API command: `uv run --directory apps/api --python 3.12 --with pytest pytest -c pytest.ini tests -q` — **53 passed**.
- Configured PostgreSQL connection to a real server, schema compatibility with `database/init.sql`, transaction rollback, and backup/restore remain unverified. Broad persistence exception handling elsewhere in `main.py` remains a known issue.
